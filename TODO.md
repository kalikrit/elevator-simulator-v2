## 🟡 Технический долг

- `TickResult.justFinished` вычисляется, но не используется. Либо задействовать, либо убрать.
- `getElevators()` возвращает ссылку на внутренний массив с типом `readonly`. В рантайме можно мутировать. Смягчить через `Object.freeze` или копию — если понадобится.
- Composable `useElevatorSystem` возвращает `elevators` как `shallowRef`, но заменяет ссылку на массив каждый кадр. Если начнёт тормозить — рассмотреть `reactive` + мутацию in-place.
- Симуляция в реальном времени (`requestAnimationFrame`) даёт небольшой разброс метрик между запусками. Для детерминированных результатов — фиксированный `deltaMs` (например, 16 мс/кадр).

## 🟢 Отложенные фичи (не в текущем scope)

- Дополнительные сценарии.
- Третий алгоритм управления.
- Сравнение более чем двух запусков (история).
- Настройка параметров (этажи, количество лифтов, скорость) через UI.
- Пассажиры как сущности с весом / приоритетом.
- Сохранение результатов между сессиями.
- Мобильная адаптация (сейчас есть простой @media < 1000px).
- Улучшение алгоритма `nearest`: учитывать вероятность попутных вызовов. Сейчас он этого не делает — и это часть дизайна, потому что контраст с `totalTime` показывает разницу алгоритмов.
- Плавное движение лифтов между этажами. Сейчас лифт «прыгает» с этажа на этаж через `Math.round`. Нужна переделка структуры: лифты вне строк `Floor`, `position: absolute` в общем контейнере.
- Return to base: лифты возвращаются на 1 этаж после N минут простоя. Нужен счётчик, обработка в `tick`, сброс при вызове. Не в scope текущего сценария.
- Сценарий с плотной нагрузкой, чтобы задействовать все 4 лифта. Сейчас «Смешанный поток» использует только 3 из 4 (лифт #3 простаивает из-за детерминированного tie-breaking «первый в списке»).
- Round-robin tie-breaking в `pickElevator` — при равенстве цен выбирать наименее занятый лифт.
